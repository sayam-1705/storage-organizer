# Security Policy

## Supported versions

Security fixes are targeted at the latest published stable release. The `main` branch may contain fixes intended for the next release. Older releases are not guaranteed to receive security updates; users should upgrade to the latest supported release.

## Reporting a vulnerability

Please do **not** report security vulnerabilities through public GitHub issues, discussions, pull requests, or commit messages.

Use GitHub's **Report a vulnerability** feature on the repository's **Security** tab when private vulnerability reporting is enabled. This creates a private report visible to the maintainers.

If the private reporting option is unavailable, contact the repository maintainer through the contact method on the maintainer's GitHub profile: <https://github.com/sayam-1705>. Ask for a private channel before sending exploit details. Do not include sensitive details in a public issue.

Please include, when safe to do so:

- A concise description of the vulnerability and its potential impact.
- The affected release, commit, operating system, and Python version.
- Reproduction steps or a minimal proof of concept using synthetic data.
- Any suggested mitigation.

Do not attach personal files, real user data, credentials, tokens, or private drive contents. Please allow maintainers reasonable time to investigate and coordinate a fix before public disclosure.

## Response expectations

The maintainer aims to acknowledge a report within seven calendar days. This is a target, not a guaranteed service level. Investigation time and release timing depend on severity, reproducibility, and available maintainer capacity.
